# ТРАЗ

**Теория решения агентных задач.**

[English](README.md) · [Проектирование по ТРИЗ](docs/TRIZ_DESIGN.md) · [Метод](docs/METHOD.md)

История работы агентов содержит опыт, который можно использовать повторно.
TRAZ сохраняет этот опыт, помогает формулировать проверяемые изменения и обновляет
рекомендации по результатам экспериментов.

Улучшение может относиться к коду, инструменту, процессу, проверке или навыку.
Каждый новый вывод остаётся гипотезой, пока для него нет результатов сравнения.

## Что уже реализовано

- Загрузка транскриптов Codex, OpenCode, JSON/JSONL и обычного текста.
- Сохранение исходных байтов без потерь, сжатие, контрольные суммы и дедупликация.
- Локальный интерфейс загрузки и CLI для использования существующими агентами.
- Подключение выбранных файлов сессий, сохранение стабильных снимков и история сборов.
- Сверка накопительных счётчиков Codex с уникальными ответами, отдельный учёт кеша
  и длительности записанных этапов без выдуманной стоимости или активного времени.
- Наблюдения о повторных вызовах, чтениях и повторяющихся явных ошибках инструментов.
- Импорт структурированных ретроспектив с привязкой к событиям исходной сессии.
- Каталог из 20 предварительных параметров и 12 механизмов разрешения противоречий.
- Разреженная матрица гипотез с отдельным журналом результатов экспериментов.
- Проверка парных сравнений с учётом накладных расходов. Успешный результат относится
  только к указанному окружению. Регрессия снимает поддержку соответствующего изменения.

Версия 0.2 проверяет структуру, арифметику и согласованность загруженных результатов.
Она пока не запускает независимые эксперименты и не доказывает истинность переданных
измерений. Автоматического изменения установленных навыков или рабочих систем нет.

## Быстрый запуск

Нужен Python 3.11 или новее. Сторонние зависимости для выполнения не требуются.

```bash
git clone https://github.com/megamen32/traz.git
cd traz
python3 -m traz --root /путь/к/личному/traz-corpus serve
```

Открой полный локальный адрес, который выведет команда. Выбери проект и загрузи
транскрипт. Оригинал сохранится в корпусе, после чего появятся наблюдения и предложения
экспериментов. В интерфейсе также можно загрузить готовый JSON с результатами сравнения.

Корпус должен находиться вне Git-репозиториев. Для длительного хранения укажи
существующий путь на нужном диске. Приложение само не выбирает и не форматирует диск,
не меняет настройки очистки на серверах и не удаляет исходные сессии.

Проверить полный цикл на синтетическом примере:

```bash
python3 examples/demo.py
```

Пример показывает переход от гипотезы к поддержке по загруженным результатам,
затем снятие поддержки после регрессии. Числа в примере проверяют работу программы,
а не эффективность настоящего агента.

## Подключение существующих сессий

Укажи точные локальные пути в [манифесте источников](examples/sources-example.json).

```bash
python3 -m traz --root /путь/к/личному/traz-corpus connect /путь/к/sources.json
python3 -m traz --root /путь/к/личному/traz-corpus collect
python3 -m traz --root /путь/к/личному/traz-corpus sources
python3 -m traz --root /путь/к/личному/traz-corpus metrics SHA256_СНИМКА
```

Повторный сбор сохраняет дополненные сессии и использует уже существующие снимки
для неизменившихся файлов. Если файл меняется при копировании, разрешена одна
повторная попытка, затем источник явно откладывается. Архив остаётся доступен,
даже если исходный файл позже исчезнет. Фоновое расписание эта команда не создаёт.

После обновления парсера команда `refresh-metadata SHA256_СНИМКА` обновит описание
покрытия только при полном совпадении индексированных событий. Ссылки из ранее
созданных разборов сохраняются. Неполный разбор и неизвестные метрики явно отмечаются.

## Как здесь применён ТРИЗ

Идеальный результат: следующая похожая задача решается лучше благодаря уже полученному
опыту, без необходимости просматривать всю историю и постоянно вмешиваться человеку.

Ключевое противоречие: история должна быть полной для исследования и небольшой
для текущей работы агента. Поэтому оригиналы, индекс и журнал экспериментов
разделены. Идеи доступны для проверки сразу, а их применение привязано к результатам
и условиям, в которых они были получены.

Новая матрица для программных задач остаётся исследовательской гипотезой.
Её пользу нужно сравнить с тем же методом без матрицы. Пустые ячейки означают,
что знания пока нет. Они не заполняются придуманной уверенностью.

## История сессий как исследовательский корпус

Повторный импорт одинаковых байтов не создаёт новое доказательство. Изменяющиеся
снимки одной нативной сессии сохраняют общую идентичность. Неизвестные и повреждённые
записи остаются в оригинале, а неполный разбор явно отмечается.

Из большого архива предполагается извлекать небольшой релевантный материал для
конкретной задачи. Часть задач нужно заранее выделять для независимой проверки:
одни и те же примеры нельзя одновременно использовать для придумывания правила
и доказательства его обобщающей способности.

Архив может содержать приватные данные и секреты. Он хранится отдельно от кода.
Сохранять нужно весь корпус, включая базу результатов и манифесты: одного сжатия
исходников недостаточно для резервирования.

Следующий существенный шаг: подключить существующий исполнитель экспериментов,
чтобы результаты поступали из реально выполненных проверок. После этого можно
оценивать полезность матрицы и постепенно автоматизировать применение изменений.

Подробные команды и ограничения находятся в [основном README](README.md).
